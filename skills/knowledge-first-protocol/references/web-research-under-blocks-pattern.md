# Веб-исследование при блокировках: практический паттерн

## Контекст

При поиске актуальных источников по SEO для Яндекса (2025–2026) часть поисковых движков и сайтов блокировала автоматический доступ. Эта заметка фиксирует рабочий паттерн для таких ситуаций.

## Общий порядок

1. **Начать с официальных источников напрямую.**
   - Избегать поисковых движков, если тема известна.
   - Примеры: `yandex.ru/support/webmaster/ru/`, `webmaster.yandex.ru/blog`, `yandex.ru/blog/search`.

2. **Использовать параллельных субагентов по категориям источников.**
   - Официальные / экспертные / технические / тренды.
   - Это снижает риск, что один заблокированный движок остановит всё исследование.

3. **При блокировке поисковика (CAPTCHA, challenge, таймаут):**
   - Не решать CAPTCHA/challenge.
   - Сразу переключаться на прямые URL известных площадок.
   - DuckDuckGo основной сайт (`duckduckgo.com/?q=...&t=h_&ia=web`) работает лучше, чем `html`/`lite` endpoints.

4. **При 404 на прямой URL статьи:**
   - Открыть раздел аналитики/блога сайта.
   - Использовать внутренний поиск площадки.
   - Проверить, не сменился ли домен.

5. **Фиксировать дату и ключевые тезисы.**
   - Для каждого источника: URL, дата публикации, 2–4 ключевых тезиса.
   - Это позволяет быстро составить сводку.

## Типичные блокировки

- Google: CAPTCHA.
- Bing: Cloudflare challenge.
- DuckDuckGo HTML endpoint: пустые результаты.
- Некоторые статьи: 404 из-за устаревших slug.
- Serpstat: таймауты.
- Affect.team: DNS-ошибки.

## Что записывать в навык

- Список проверенных источников с URL.
- Ключевые тезисы / цитаты.
- Даты публикаций.
- Противоречия между источниками.
- Практический чек-лист.
- Проблемы и обходы (эта заметка).
