# Параллелизм агентов и многопользовательская работа

Два независимых уровня: пул субагентов Hermes и гейтвей, обслуживающий несколько сессий сразу.

## 1. delegate_task — субагенты Hermes

| Параметр | Значение |
|---|---|
| Лимит одновременных детей | `delegation.max_concurrent_children` в `~/.hermes/config.yaml`. **Проверяй живое значение, не помни**: `grep -A6 '^delegation' ~/.hermes/config.yaml` |
| Что при превышении | весь batch отклоняется с `Too many tasks: N provided, but max_concurrent_children is M`; лишние задачи **не** встают в очередь и позже не запускаются |
| Модель детей | из того же блока `delegation.model`; пер-задачной модели у `delegate_task` нет, `inherit_mcp_toolsets: true` отдаёт детям MCP-тулсеты родителя |
| Изоляция | у каждого ребёнка свой контекст, терминал и рабочая директория; спросить родителя он не может |

Пул считается только по `delegate_task`. Отдельные OS-процессы CLI-агентов (OpenCode, Codex, Claude Code)
в него не входят, но запускать их стоит только по явной просьбе пользователя — см.
`superpowers-workflow` → `references/opencode-vs-subagents.md`.

## 2.0 Три уровня, которые легко перепутать

| Уровень | Сколько | Что это |
|---|---|---|
| Процесс (рантайм) | один `hermes-gateway`, отдельно WebUI и CLI | общий хост на все платформы и всех пользователей |
| Агент | один на **сессию** (чат) | объект `AIAgent`: полный инструментарий, своя история, персонаж, оверрайд модели; живёт в кэше по `session_key` |
| Субагент | до `delegation.max_concurrent_children` на сессию | `delegate_task`: свой контекст, свой терминал, без вопросов к пользователю и без вложенного делегирования |

«Полноценный Hermes на пользователя» верно про **возможности** агента и неверно про **процессы**: на
пользователя заводится сессия с полноценным агентом внутри общего процесса, а не отдельная программа.
Субагенты не открываются «на пользователя» автоматически — их запускает агент под конкретную задачу.
Поэтому вопрос «ты сейчас субагент?» разводится так: ассистент в диалоге — это агент сессии, а субагенты —
те, кого он вызвал.

## 2. Гейтвей — несколько пользователей одновременно

Сессия ключуется парой платформа+чат: личка Telegram — `agent:main:telegram:dm` (принадлежность
определяется записью origin/sender в `state.db`, а не id в ключе), WebUI — `agent:main:web:*`.
Три пользователя = три сессии = три независимые истории и три объекта `AIAgent`.

- **Между сессиями параллельность настоящая.** Ходы исполняются в `_UnboundedThreadExecutor`
  (`gateway/run.py`) — намеренно неограниченном: тело хода держит поток целиком (каждый вызов инструмента
  блокирует), и конечный пул молча ставил бы уже принятые ходы в очередь друг за другом.
- **Внутри одной сессии — не более одного живого хода.** Это корректность, а не настройка: файловый
  реестр лизов `runtime/active_sessions.json` + `active_sessions.lock` (`fcntl`), поэтому эксклюзив
  соблюдается и **между процессами** — один диалог нельзя вести одновременно из CLI, гейтвея и WebUI.
  При неопределённости владения отказ закрытый.
- **Занятая сессия** — `display.busy_input_mode`: `interrupt` (дефолт) прерывает текущий ход ради нового
  сообщения, `queue` ставит в очередь, `steer` вклинивает текст в идущий ход.
- **Приёмный лимит** — `max_concurrent_sessions` (top-level или `gateway.max_concurrent_sessions`),
  по умолчанию не задан. При превышении: `Rejecting new active session <key>: max_concurrent_sessions reached`.
  Это политика ресурсов — в отличие от эксклюзива сессии, который безусловен.
- **Давление памяти** — кэш объектов `AIAgent` на сессию вытесняется под memory pressure
  (`gateway/agent_cache_pressure.py`).
- **Память и скиллы живут на профиль, не на сессию**: `~/.hermes/memories/MEMORY.md`, `USER.md`,
  `~/.hermes/skills/`. Несколько людей на одном боте делят память, профиль пользователя, скиллы и файловую
  систему; личные сообщения не смешиваются, а знание о пользователе — общее. Изоляция достигается только
  профилями: `multiplex_profiles` + маршруты `profile_routes`, `hermes profile create NAME`.
- **Доступ закрыт до входа в агента**: `TELEGRAM_ALLOWED_USERS`, `hermes pairing`, групповые allowlist.

Итог одной фразой: параллельность идёт **по сессиям** (по пользователям), а внутри сессии — строго по
одному ходу за раз.

## 3. Как это проверять, а не вспоминать

```bash
ps -eo pid,cmd | grep hermes_cli.main          # какая ревизия работает прямо сейчас
hermes sessions stats                          # сколько сессий и сообщений
ls ~/.hermes/state/                            # gateway.heartbeat, lifecycle, runtime/
```

Механику ищи в исходниках: `grep -rn "<механизм>" ~/.hermes/hermes-agent/gateway/*.py`. Инварианты
в `gateway/run.py` и `hermes_cli/active_sessions.py` сформулированы прямым текстом — цитируй их, а не
пересказывай по памяти.
