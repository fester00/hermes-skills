## 📍 Модуль 1: Истоки

### 1.1 Установка, Cargo и первая программа

**Простая истина:** Cargo — единый инструмент для создания, сборки, зависимостей, тестов. Стандартный проект: `Cargo.toml` (манифест) + `src/main.rs` (точка входа).

**Ключевой код:**
```rust
fn main() {
    println!("Привет, ученик!");
}
```

**Подводные камни для Python/JS:**
- `println!` — макрос (`!`), не функция. Макросы разворачиваются до компиляции и могут принимать переменное число аргументов.
- `Cargo.toml` — жёсткий манифест. `Cargo.lock` делает сборки детерминированными.

**Практика:**
1. Установить `rustup`: `curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh`
2. `cargo new project_name --bin`
3. `cargo run` — собрать и запустить

### 1.2 Переменные, мутабельность, типы данных

**Простая истина:** В Rust переменная — это обещание. `let` обещает неизменность. `let mut` — осознанное разрешение на изменение. Shadowing (`let x = ...; let x = ...;`) — создание новой переменной с тем же именем, не мутация.

**Ключевой код:**
```rust
let a = 5;          // неизменяемая
let mut b = 10;     // изменяемая
b = 15;

let x = "42";
let x = x.parse::<i32>().unwrap();  // shadowing: новая переменная, другой тип
```

**Подводные камни:**
- Shadowing ≠ мутация. Старая переменная остаётся валидной — ссылка на неё не ломается.
- **Shadowing при наличии ссылок:** если `let a = 10; let c = &a; let a = a + 1;` — ссылка `c` остаётся валидной, потому что старая `a` живёт до конца блока. Это безопаснее `mut`, где изменение `a` сломало бы активные неизменяемые ссылки.
- **Затенение в цепочке преобразований:** `let price = 1000.0; let price = price * 0.9; let price = price * 1.2;` — каноничный Rust-стиль для последовательных вычислений. Предпочтительнее `mut`, так как не ломает ссылки на промежуточные значения.
- `parse::<i32>()` — турбофиш (`::<type>`). Указывает компилятору конкретный тип.

**Практика:**
Написать конвертер температуры тремя способами:
- Через новую переменную
- Через `mut`
- Через shadowing

### 1.3 Функции, управление потоком (if, loop, match)

**Простая истина:** В Rust всё — выражение (expression). Последнее выражение функции автоматически возвращается (без `return`, без точки с запятой в конце). `if`, `match`, `loop` — тоже выражения с типом.

**Ключевой код:**
```rust
fn describe(x: i32) -> &'static str {
    if x > 0 { "положительное" } else { "не положительное" }
}

fn match_example(n: i32) -> &'static str {
    match n {
        1 => "Один",
        2..=5 => "Два-пять",
        _ => "Другое",
    }
}
```

**Подводные камни:**
- Точка с запятой превращает выражение в инструкцию. `a + b;` → возвращает `()`.
- `match` требует **все** варианты. Компилятор не простит забытую ветку.
- `loop { break 42; }` возвращает `42`. Python так не умеет.

**Практика:**
Функция `day_of_week` через `match` для чисел 1-5, с `_` обработкой остальных.

### 1.4 Владение (Ownership): сердце Rust

**Простая истина:** Каждое значение в Rust имеет **владельца** (owner). Владение уникально — у данных может быть только один владелец. Когда владелец выходит из области видимости, память автоматически освобождается. Значения перемещаются по умолчанию.

**Ключевой код:**
```rust
let s1 = String::from("привет");
let s2 = s1;       // владение ПЕРЕДАНО (move). s1 больше нельзя использовать!
// println!("{}", s1); // ОШИБКА! значение moved
```

**Подводные камни для Python/JS:**
- В Python `b = a` копирует ссылку. В Rust — передаёт **владение** (или копирует, если тип реализует `Copy`).
- Примитивы (`i32`, `f64`, `bool`) реализуют `Copy` — копируются. Составные типы (`String`, `Vec`) — move.
- Когда функция принимает значение, она становится владельцем. Если хочешь вернуть — надо вернуть из функции.

**Почему это важно для бэкенда:** В многопоточности нет двух владельцев одних данных → нет data races.

### 1.5 Заимствование (Borrowing) и ссылки

**Простая истина:** Вместо передачи владения можно **заимствовать** — взять ссылку (`&`). Можно иметь сколько угодно неизменяемых ссылок (`&T`) ИЛИ одну изменяемую (`&mut T`), но не оба одновременно.

**Ключевой код:**
```rust
fn print_length(s: &String) {
    println!("{}", s.len());
}

fn append_exclamation(s: &mut String) {
    s.push('!');
}

let mut text = String::from("привет");
print_length(&text);      // неизменяемое заимствование
append_exclamation(&mut text);  // изменяемое
```

**Правила заимствования:**
1. Одна изменяемая ссылка ИЛИ любое количество неизменяемых
2. Ссылки должны быть валидны (не висячие)
3. Изменяемая ссылка запрещает неизменяемые

**Практика:** Написать функцию, которая принимает `&mut Vec<i32>` и удваивает каждый элемент.

### 1.6 Время жизни (Lifetimes): первое знакомство

**Простая истина:** Компилятор проверяет, живут ли ссылки достаточно долго. В большинстве случаев он выводит lifetimes сам (`'_` неявно). Главное правило: возвращаемая ссылка должна жить не дольше, чем входные данные.

**Ключевой код:**
```rust
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str {
    if a.len() > b.len() { a } else { b }
}
```

**Аналогия:** `<'a>` — это подпись контракта: «я обещаю, что результат не переживёт ни один из аргументов». Вместо `String` → `str` (строковый срез) — это ссылка на строку, не владение.

## 🔧 Модуль 2: Строительные Блоки

### 2.1 Структуры (struct) и перечисления (enum)

**Простая истина:** `struct` группирует данные (как `class` без наследования). `enum` — перечисление вариантов Rust-стиля: каждый вариант может содержать данные.

**Ключевой код:**
```rust
struct User {
    name: String,
    age: u32,
    active: bool,
}

enum HttpStatus {
    Ok,
    NotFound(u32),        // вариант с данными: код
    Error { code: u32, message: String }, // именованные поля
}
```

**Подводные камни:**
- `enum` в Rust — это **ADT (algebraic data type)**. Не просто константы — мощный инструмент моделирования.
- `Option<T>` и `Result<T, E>` — это тоже `enum` (stdlib).

### 2.2 Сопоставление с образцом (Pattern Matching)

**Простая истина:** `match` + деструктуризация — главный инструмент обработки enum. Он **гарантирует** обработку всех вариантов.

**Ключевой код:**
```rust
enum Message {
    Text(String),
    Number(i32),
    Quit,
}

fn handle(msg: Message) -> String {
    match msg {
        Message::Text(s) => format!("Текст: {}", s),
        Message::Number(n) => format!("Число: {}", n),
        Message::Quit => String::from("Пока!"),
    }
}
```

**Модный синтакс:**
```rust
if let Message::Text(s) = msg { ... }       // только один вариант
while let Some(value) = iter.next() { ... } // цикл по итератору
```

### 2.3 Векторы, строки, хеш-таблицы

| Тип | Объявление | Примечание |
|-----|------------|------------|
| Вектор | `Vec<T>` | `vec![]` макрос. `push`, `get` (возвращает `Option<&T>`) |
| Строка | `String` | UTF-8. `&str` — строковой срез (заимствование). |
| HashMap | `HashMap<K, V>` | `insert` передаёт владение ключом и значением. |

**Подводные камни:**
- `vec.get(5)` — возвращает `Option<&T>`, не `T`. Нужен `match` или `if let`.
- `String` ≠ `&str`. `String` — владение, `&str` — срез (заимствование).

### 2.4 Обработка ошибок: Result и Option

**Простая истина:** Rust не любит исключения. Вместо них — два enum:
- `Option<T>` — либо `Some(T)`, либо `None` (отсутствие значения)
- `Result<T, E>` — либо `Ok(T)`, либо `Err(E)` (ошибка)

**Ключевой код:**
```rust
fn find_user(id: u32) -> Option<User> { ... }
fn read_file(path: &str) -> Result<String, io::Error> { ... }

// Обработка:
let user = find_user(42)?;     // `?` — early return Err/None из функции
let content = read_file("log.txt")?;

// Методы:
let x: Option<i32> = Some(5);
let doubled = x.map(|v| v * 2);  // Some(10)
let with_default = x.unwrap_or(0); // 5 (если Some) или 0 (если None)
```

**Подводные камни для Python/JS:**
- Python: `None` молча течёт по коду. Rust: `None` — совершенно другой тип, помеченный `Option`. Компилятор **заставит** обработать его.
- `unwrap()` — паника. Не используй в production. Используй `?`, `match`, `if let`, `unwrap_or`.

### 2.5 Генерики (Generics) и Типажи (Traits)

**Простая истина:** Generics — параметризация типами (как `List<T>`). Traits — интерфейсы (как `interface` в TS), но с супер-силой реализации для чужих типов.

**Ключевой код:**
```rust
// Generic
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];
    for item in list {
        if item > largest { largest = item; }
    }
    largest
}

// Trait + реализация
pub trait Summary {
    fn summarize(&self) -> String;
}

pub struct NewsArticle { ... }
impl Summary for NewsArticle {
    fn summarize(&self) -> String { ... }
}
```

**Почему Traits мощнее интерфейсов:**
- **Orphan rule:** можно реализовать trait для чужого типа (если либо trait, либо тип — локальный). Это "расширение" чужих классов без наследования.
- Trait bounds: `T: Display + Clone` — сложные ограничения.

### 2.6 Время жизни в структурах и типажах

**Простая истина:** Если структура хранит ссылки (не владеет), она должна указать lifetime.

**Ключевой код:**
```rust
struct Book<'a> {
    title: &'a str,  // ссылка с временем жизни 'a
}

impl<'a> Book<'a> {
    fn title_length(&self) -> usize {
        self.title.len()
    }
}
```

## 🎨 Модуль 3: Инструменты Ремесленника

### 3.1 Модули, пакеты (crates), область видимости

- `mod` — определение модуля (файл `foo.rs` = модуль `foo`).
- `pub` — публичность (по умолчанию — `private`).
- `use` — импорт.
- `crate::` — корень текущего крейта.

```rust
mod network {
    pub fn connect() {}
    mod server { ... }
}

use crate::network::connect;
```

**Подводные камни:**
- В отличие от JS/Python, видимость строгая по умолчанию. Забыл `pub` — не достучишься.

### 3.2 Тестирование кода

**Встроенное тестирование:**
```rust
#[cfg(test)]
mod tests {
    use super::*;

    #[test]
    fn it_works() {
        assert_eq!(2 + 2, 4);
    }

    #[test]
    #[should_panic]
    fn it_panics() { panic!("boom"); }
}
```

`cargo test` запускает тесты. `cargo test -- --nocapture` — с `println`.

### 3.3 Замыкания (Closures) и Итераторы

**Замыкания (анонимные функции, захватывающие окружение):**
```rust
let factor = 2;
let doubled = |x| x * factor;  // замыкание захватило factor
```

**Итераторы** — ленивые, цепочечные (как генераторы Python, но типобезопасные на этапе компиляции):
```rust
let sum: i32 = (1..=100)
    .filter(|x| x % 2 == 0)
    .map(|x| x * x)
    .sum();
```

**Подводные камни:**
- `.collect()` требует явной типизации: `let v: Vec<i32> = iter.collect();` или турбофish: `iter.collect::<Vec<i32>>()`.
- Итераторы потребляют коллекцию. После `for x in vec` vec перемещён (можно обойтись `&vec` или `vec.iter()`).

### 3.4 Умные указатели: Box, Rc, Arc

- `Box<T>` — данные на куче, но владение одно.
- `Rc<T>` — счётчик ссылок (single-threaded). Несколько владельцев, но не `mut`.
- `Arc<T>` — атомарный счётчик (thread-safe). Для многопоточности.
- `RefCell<T>` — внутренняя мутабельность во время выполнения (runtime borrow checking).

```rust
use std::rc::Rc;
let data = Rc::new(String::from("shared"));
let data2 = Rc::clone(&data);  // счётчик +1
```

### 3.5 Многопоточность: spawn, channels, Mutex, RwLock

- `thread::spawn(|| { ... })` — создать поток.
- `mpsc::channel()` — каналы (message passing).
- `Mutex<T>` — взаимное исключение (one writer at a time).
- `RwLock<T>` — читателей много, писатель один.

**Ключевой код:**
```rust
use std::sync::{Arc, Mutex};
use std::thread;

let counter = Arc::new(Mutex::new(0));
let mut handles = vec![];

for _ in 0..10 {
    let counter = Arc::clone(&counter);
    let handle = thread::spawn(move || {
        let mut num = counter.lock().unwrap();
        *num += 1;
    });
    handles.push(handle);
}

for handle in handles { handle.join().unwrap(); }
println!("Result: {}", *counter.lock().unwrap());
```

**Почему Rust безопасен для потоков:** Компилятор не даст отправить `Rc` между потоками (типаж `Send`). Нужен `Arc`. Не даст `&mut` из разных потоков на одни данные. Ошибки data race — compile-time, не runtime.

### 3.6 Первый шаг в async/await

- `async fn` — функция, возвращающая `Future` (задачу, которую можно выполнить).
- `await` — приостановка (не блокирует поток), делегирование рантайму.
- Сам `async` — это кооперативная многозадачность. Фактическое исполнение — через runtime (Tokio, async-std).

```rust
async fn fetch_data() -> String {
    // некая асинхронная операция
    "data".to_string()
}

#[tokio::main]
async fn main() {
    let result = fetch_data().await;
    println!("{}", result);
}
```

## ⚡️ Модуль 4: Продвинутые Концепции

### 4.1 Глубокое погружение в Lifetimes

**Сложные сценарии:**
- Lifetime ellision (неявные): компилятор сам выводит в простых случаях.
- Lifetime subtyping: `'a: 'b` означает «`'a` живёт не меньше `'b`».
- Lifetime в замыканиях (higher-ranked trait bounds): `for<'a> Fn(&'a str)`.

### 4.2 Типажи-объекты (Trait Objects) и динамическая диспетчеризация

- `&dyn Trait` — trait object (динамический). Размер неизвестен в compile-time.
- `impl Trait` — статический (zero-cost). Компилятор знает тип.

```rust
fn trait_object(items: &Vec<Box<dyn Drawable>>) { ... }
fn static_impl(item: impl Drawable) { ... }
```

### 4.3 Макросы: declarative и proc macros

- `macro_rules!` — «declaration macros». Паттерн-матчинг на уровне AST.
- `proc_macro` — процедурные макросы (например, `#[derive(Serialize)]` от serde).

### 4.4 Unsafe Rust: когда и зачем

`unsafe` — **не** значит «запустить без проверок». Значит «я, программист, беру на себя ответственность за соблюдение правил». Компилятор всё ещё проверяет типы, но разрешает:
- Разыменование сырых указателей (`*const T`, `*mut T`)
- Вызов `unsafe fn`
- Доступ к `static mut`
- FFI (вызов C-кода)

### 4.5 Async в деталях: Future, Runtime, Tokio

- `Future` — трейт с методом `poll()`.
- Executor — event loop, который вызывает `poll()`.
- Tokio — самый популярный runtime. Предоставляет:
  - `tokio::net::TcpListener`
  - `tokio::time::sleep`
  - `tokio::sync::mpsc`
  - `tokio::fs` — асинхронный файловый ввод-вывод

### 4.6 Работа с файлами, сетью, сериализация (serde)

**Serde:**
```rust
use serde::{Serialize, Deserialize};

#[derive(Serialize, Deserialize)]
struct User {
    name: String,
    age: u32,
}

let user = User { name: "Панда".into(), age: 42 };
let json = serde_json::to_string(&user)?;
```

## 🚀 Модуль 5: Мастерство — Построение Веб-Бэкенда

### 5.1 Веб-фреймворки: Axum vs Actix Web vs Rocket

| Фреймворк | Подход | Когда выбрать |
|-----------|--------|---------------|
| **Axum** | Поверх Hyper + Tower (композиция из middleware) | Дефолтный выбор сегодня. Прямое использование Tokio/Hyper. Баланс простоты и мощи. |
| **Actix Web** | Actor-модель | Если нужен максимальный throughput. Чуть более сложная модель. |
| **Rocket** | Макросы + атрибуты | Если хочется минимум бойлерплейта. Требует nightly (или версия 0.5+ на stable). |

### 5.2 REST API: маршруты, обработчики, middleware

```rust
use axum::{routing::get, Router};

```

```rust
use tower::ServiceBuilder;

    .layer(ServiceBuilder::new().layer(TraceLayer::new_for_http()));
```

- Compile-time проверка SQL-запросов (через `sqlx prepare`).

- Поддерживает Postgres, MySQL, SQLite.

- **Состояние (State):** `Router::with_state(AppState { db: pool, config })`

### 5.5 Логирование, обработка ошибок на уровне сервиса

- **`tracing`** — structured logging (замена `log` + `env_logger`).
- **`anyhow`** — для приложений: удобная обёртка ошибок.
- **`thiserror`** — для библиотек: типизированные ошибки через derive.

```rust

use thiserror::Error;

#[derive(Error, Debug)]

    #[error("Database error: {0}")]
    Database(#[from] sqlx::Error),
    #[error("Not found")]
    NotFound,
```

### 5.6 Сборка, Docker, деплой в продакшн

**Сборка:**
```bash
cargo build --release   # оптимизированный бинарник в target/release/
```

**Docker (минимальный):**
```dockerfile
# Multi-stage build
FROM rust:1.70 as builder
WORKDIR /app
COPY . .
RUN cargo build --release

FROM debian:bullseye-slim
RUN apt-get update && apt-get install -y ca-certificates
COPY --from=builder /app/target/release/myapp /usr/local/bin/
CMD ["myapp"]
```

**Важно:** Статически линкованный бинарник Rust — обычно один файл. Можно даже использовать `FROM scratch` (пустой базовый образ) — если нет динамических зависимостей.

**CI/CD:** Гоночные лошадки — `cross` для кросс-компиляции, `cargo audit` для проверки уязвимостей, `clippy` для линтинга.

## ⚠️ Топ-10 Подводных Камней (для Python/JS-разработчиков)

1. **`let` без `mut` нельзя изменить.** Никогда. Компилятор — страж.
2. **Move-семантика.** `s1 = s2` для `String` — move, не копия. `s1` больше нельзя использовать.
3. **Ссылки и владение.** Нельзя иметь `&mut` и `&` одновременно. Это не запутанность — это защита.
4. **`unwrap()` — паника.** Не используй в production. Любишь `None` в Python? Тут `None` — тип, и его обязаны обработать.
5. **Точка с запятой = `()`.** `return a + b` vs `a + b` — разные миры.
6. **Lifetime annotations.** Если структура хранит ссылки — нужны `'a`. Это не сложность, это документирование контракта.
7. **Итераторы потребляют.** `for x in vec` — vec moved. Используй `&vec` или `vec.iter()`.
8. **Trait vs interface.** Можешь реализовать чужой trait для своего типа. Можешь реализовать свой trait для чужого типа. Но не оба чужих.
9. **`async fn` — не магия.** Она возвращает `Future`. Для `.await` нужен runtime (Tokio).
10. **`cargo` — не `npm`.** Зависимости фиксируются в `Cargo.lock`. Сборка детерминированна. Обожаемая надежность.
