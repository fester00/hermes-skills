# Перенос редизайна и сверка ссылок (SEO-parity)

Как принимать перенесённую версию сайта так, чтобы вопрос владельца «ссылки остались теми же, SEO не пострадает?»
получал ответ числами, а не обещанием. Дополняет раздел «HTML-семантика и перелинковка» в SKILL.md.

## 1. Сверка ссылок по всей карте сайта — обязательный шаг приёмки

Инструменты (в лаборатории `pentajunior-redisine/scripts/`):

- `verify-links.py` — сплошная сверка: по каждому адресу из карты сайта сравнивает живую версию и новую.
- `verify-links-detail.py` — разбор расхождений: что пропало и что появилось, с проверкой живучести каждой ссылки.
- `verify-links-final.py` — финальная сверка с учётом переадресаций (именно она снимает ложную тревогу).

Порядок:

1. Взять адреса из `http://localhost:3000/sitemap.xml` (в этом проекте 143 адреса), отбросить сам xml.
2. По каждому адресу на обоих портах снять: код ответа (`curl -sL … -w %{http_code}`), canonical и **множество
   внутренних ссылок на страницы** — только те, что начинаются с `/`, без `/_next/`, без путей к ассетам и
   расширений файлов (`.css/.js/.png/.webp/.svg/.xml/.txt/.pdf/.json`).
3. Вердикт строится из трёх чисел: расхождений кодов ответа, расхождений canonical, страниц с иным набором
   ссылок. Плюс считать уникальные ссылки на `/production/*` со страницы товара против живой версии
   (в этом проекте после возврата бокового списка — 49 из 49).
4. Расхождения разбирать **по одной ссылке**, а не списком (см. ниже) — иначе получится ложная потеря.

## 2. Ловушка «потерянных» ссылок: короткий адрес отдаёт 308 на канонический

На старом сайте часть ссылок в статьях блога ведёт на короткие двухуровневые адреса вида
`/production/<категория>/<товар>`, а такие адреса отдают **308** на правильный трёхуровневый. При проверке
через `curl -sL` они выглядят как рабочие (200), поэтому первый прогон сообщает «потеряно 56 рабочих ссылок» —
и это неправда.

Правило: потерянной считать ссылку только тогда, когда её **итоговый** адрес не встречается на новой странице.

```bash
curl -sL -o /dev/null -w '%{url_effective}' http://localhost:3000/<короткий-адрес>
```

Если итоговый адрес есть среди ссылок новой версии (в том числе среди итоговых адресов её собственных
ссылок) — потеря нулевая: новая версия ведёт сразу по каноническому адресу, то есть без лишнего перехода.
Это улучшение, так и докладывать. Появление новых рабочих ссылок (например, подкатегории на странице каталога)
— отдельная строка в отчёте, тоже проверенная на 200.

## 3. Правка статичных страниц набора: по блокам, а не окнами

- Признак «есть ли фото/нужный узел» определять **внутри самой карточки**: выделять блок регэкспом
  (`<li>\s*<div class="c-cat">.*?</li>` с `re.S`) и подменять через `re.sub(..., функция, ...)`. Окно в N
  символов после найденного `href` заходит в соседнюю карточку: проверка «в блоке уже есть `<img>`» даёт
  ложное «да», и карточка без фото остаётся с заглушкой.
- `str.replace(old, new, 1)` по подстроке опасен — заменяет первое вхождение в файле, а не в блоке. Только
  блочная подстановка, после неё пересчитать вхождения.
- После правки сверять: число карточек, из них с фото, что у всех `<img>` непустой `alt`, и что все пути
  указывают на существующие файлы (`pathlib.Path(...).exists()`).

## 4. Фотографии: переносить из проекта, а не выдумывать

- Ассеты набора в лаборатории обычно беднее проекта: `public/images` набора ≠ `/home/natan/pentajunior-v2/public/images`.
  Карточки рисуются заглушками и выглядят как дефект дизайна. Перед выводами сверить с проектом и перенести
  недостающие файлы, сохраняя структуру каталогов; кириллицу в путях кодировать `urllib.parse.quote`.
- Сначала проверить, есть ли фото **на живом сайте** вообще: у одной категории его нет и там — честная заглушка,
  URL выдумывать нельзя.
- `alt` брать с живого сайта (тот же файл → та же подпись), а не сочинять.

## 5. Партиалы набора: пути зависят от глубины страницы

Шапка и подвал набора лежат уровнем выше страниц, которые их вставляют: путь `../public/images/fav.svg`
работает на главной набора, но даёт 404 на страницах внутри набора. В партиалах держать
`../../public/images/...` и править сразу во всех наборах (иначе следующая страница повторит ошибку).

## 6. Снимок — только с прокруткой

Ленивые фотографии в нижних рядах не успевают загрузиться, и 8 из 13 карточек на снимке выглядят пустыми:
это легко принять за дефект вёрстки и пойти «чинить» здоровую страницу. Готовый инструмент —
`pentajunior-redisine/scripts/shot-full.cjs`: прокручивает страницу до низа, ждёт загрузки всех изображений,
печатает `imagesTotal / broken / stillPending / failedRequests` и снимает либо всю страницу, либо кадр с заданным
смещением (четвёртый аргумент — смещение). Смотреть глазами только после такого снимка.

## 7. Приёмка набора направлений

`python3 scripts/verify-pages.py` прогоняет все страницы лаборатории (A/B/C) на 1440 / 768 / 375 и сверяет мета
с живыми двойниками. Список пар живёт в самом скрипте — при добавлении нового набора **дописывать пары**, иначе
его страницы молча не попадут в общую приёмку. Критерий готовности: «страниц с расхождением SEO: 0 из N»,
переполнение 0 на всех ширинах, все изображения загружены, общий слой набора (`base.css`) не тронут.
