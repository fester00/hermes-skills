## Решения по спецслучаям

### article-05 — переосмысление темы

Исходно: статья про FDA/BfR/СЭЗ/ГОСТ пищевого силикона, `published: false`. Невозможно починить удалением пищевки (вся статья про неё). Применён **паттерн переосмысления темы**:

- Новый `id`: `remont-silikonovoj-formy-svoimi-rukami` (старый освобождается).
- Новые `title`, `metaTitle`, `metaDescription`, `keywords`, `relatedProducts` ([`unisil-9629`,`unisil-9500`] → [`unisil-9110`,`unisil-9131`]), `publishDate` (2026-03-22 → 2026-08-18), `published: true`.
- Новая тема — «Ремонт силиконовой формы».
- Перед заменой темы проверить, что новая тема не пересекается с существующими статьями (SERP + поиск `id` в `src/data/blog/`).

После переосмысления build gate стал **158/158** (а не 157/157) — новая `article-05` теперь `published: true`. Это нормальная аномалия, не баг.

### article-15 — расширение пищевой тематики (ТСМ-1)

Исходно: статья про хлебопекарную тему, в которой была «Применение в смежных отраслях» с пищевыми расширениями (мармелад, карамель, шоколад). На середине сессии пользователь явно сказал: «для товара ТСМ-1 мы можем упоминать о пищевой продукции — есть сертификат». После этого блок вернулся в расширенной форме + добавлены новые применения (заморозка полуфабрикатов, упаковка). Это подтверждение правила: ТСМ-1 имеет сертификат, расширенная пищевая тема легитимна.

Урок: **после середины сессии правила могут измениться — нужно быть готовым переделать уже сделанные статьи**. Для `article-15` была сделана переделка через `patch` (не полный rewrite), чтобы не потерять уже согласованную базу.

### article-16 — баг в исходнике

В исходном файле:

```ts
relatedProducts: ["penta-811,penta-870"],
```

TypeScript это принял (строка как один элемент массива), но по факту это один ID `"penta-811,penta-870"`, а не два. Исправлено на:

```ts
relatedProducts: ["penta-811", "penta-870"],
```

**Перед каждым рерайтом** прогонять grep `grep -E 'relatedProducts:\s*\["[^"]*,[^"]*"\]' src/data/blog/` — искать comma-в-string-pattern, который TypeScript пропускает.

## Workflow-паттерны этой сессии

1. **read_file без offset/limit** для каждой статьи — чтобы видеть DNA-паспорт целиком, не огрызками.
2. **execute_code + Playwright SERP** для каждой статьи — проверка позиции и подгрузка топ-конкурента. Скрипты лежат в `/tmp/article0N_*.py`. Постоянный Chrome profile: `/mnt/data/natan-storage/.chrome-vk-profile`.
3. **Предложение варианта вступления A** пользователю перед началом рерайта (для первых статей). После того как пользователь подтвердил стиль A — применять без повторного согласования.
4. **write_file** для полного rewrite (для большинства статей) или **patch** для точечных правок (для `article-15` после расширения темы).
5. **search_files** с грепом `(пищев|медицин|кондитер|FDA|BfR|протез|имплантат)` после каждой правки — подтверждение отсутствия запрещённых слов.
6. **build gate** через `export PATH="/home/natan/.nvm/versions/node/v24.13.1/bin:$PATH"` обязательно — без nvm Node 18.x, и Next.js 16 падает.
7. **git diff не показан** между статьями (только в финале). Пользователь сказал «давай» сразу после итогового summary — коммит одним большим commit'ом `16ae10b` с описанием всех 16 файлов.

- **Не загружался `humanizer`-скилл** напрямую — все 4 раза возвращали `[SKILL_PRUNED]`. Применялись паттерны humanizer-стиля по памяти (убирали псевдо-цифры, водяные анонсы, «Ниже — все ключевые параметры»). Если в будущей сессии humanizer вернётся — обязательно прогнать против 34 паттернов.
