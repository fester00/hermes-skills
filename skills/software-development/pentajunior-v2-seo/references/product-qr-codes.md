# QR-коды для товаров (упаковка → карточка с инструкцией)

Когда пользователь просит «сделать QR для товаров, чтобы при считывании открывалась страница с инструкцией».

## Решение пользователя (pentajunior-v2)

- QR кодирует **адрес карточки товара напрямую** (без редиректа) и **с якорем `#application-heading`**, чтобы сканирование сразу открывало блок «Применение» (там лежит пошаговая инструкция из `template_data`).
- Короткая промежуточная ссылка `/i/<код>` с редиректом **не используется** — это осознанный выбор. Ограничение: если адрес карточки изменится, напечатанные QR сломаются (нужна перепечатка). Редирект — единственный способ менять цель без перепечатки; предлагать его уместно один раз, как опцию, и не переспрашивать.
- Ассеты — просто файлы в `public/qr/` (+ архив для передачи), **без админ-страницы**: пользователь предпочитает минимальный прямой результат (файлы) новой инфраструктуре (UI в админке).

## Адрес карточки

`https://pentajunior.ru/production/<category.slug>/<subcategory.slug>/<product.id>` + `#application-heading`.
Слаги брать из SQLite (`categories.slug`, `subcategories.slug`), не сочинять.

## Генерация (без зависимостей в проекте)

Ставить `qrcode` в **отдельной temp-папке**, не в проекте:

```bash
mkdir -p /mnt/data/natan-storage/tmp/qrgen && cd /mnt/data/natan-storage/tmp/qrgen
npm i qrcode jsqr pngjs --no-audit --no-fund
node gen.js
```

На каждый товар — SVG (для типографии) + PNG 1000px (превью):
```js
await QRCode.toFile(svg, url, { type: 'svg', errorCorrectionLevel: 'M', margin: 4 });
await QRCode.toFile(png, url, { type: 'png', width: 1000, errorCorrectionLevel: 'M', margin: 4 });
```

## Проверка (обязательна — «декодируй обратно»)

1. Каждый PNG раскодировать и сверить с URL:
```js
const png = PNG.sync.read(fs.readFileSync(pngPath));
const decoded = jsQR(new Uint8ClampedArray(png.data), png.width, png.height);
if (!decoded || decoded.data !== url) throw new Error('QR mismatch');
```
2. Каждую целевую страницу проверить на проде: HTTP 200 **и** наличие `id="application-heading"` в HTML — иначе якорь не сработает и QR откроет верх карточки.

## Именование и артефакты

- Имена — по чистой марке (`unisil-9220`), **не** по сырому id: у части Юнисилов id начинается с дефиса (`-9220`), с ним неудобно в именах файлов.
- В `public/qr/`: `<код>.svg`, `<код>.png`, `manifest.csv` + `manifest.json` (файл → товар → URL), `README.txt` с рекомендациями печати.
- Архив для передачи — `python3` + `zipfile` в рабочую папку пользователя; путь назвать в ответе.

## Печать

- Минимальная сторона 20–25 мм (комфортно 25–30 мм); белое поле (quiet zone) 4 модуля уже включено — не обрезать; чёрный по белому, без глянца/градиентов; уровень коррекции M.

## Питфоллы

- «Все, кроме X» — фильтровать по id/названию и **явно перечислить** в ответе исключённые и **отсутствующие в каталоге** модели (упомянутых позиций может просто не быть в БД).
- `sqlite3` CLI на хосте нет — id/слаги брать через `python3` (`import sqlite3`).
- Охват «все Юнисилы» = подкатегории «платиновые» + «оловянные» (категория 1); ЮниКаст/ЮниФлекс/Люминофор — отдельные марки и в «Юнисилы» не входят, хотя инструкции в `template_data` есть и у них.
