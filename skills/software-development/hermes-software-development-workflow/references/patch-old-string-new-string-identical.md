## Проблема

При обновлении файла через `patch` со старым `old_string`, который уже был изменён или удалён, `patch` возвращает ошибку:

```
File-mutation verifier: 1 file(s) were NOT modified this turn
 • <path> — [patch] old_string and new_string are identical
```

Это значит, что `old_string` и `new_string` совпадают, и изменений не произошло. Это **не критичная ошибка**, но она создаёт шум и указывает на избыточный вызов.

## Причины

1. **Повторный `patch`** после того, как файл уже был изменён другим инструментом (например, `write_file` или предыдущим `patch`).
2. **Копирование текущего содержимого** файла в `old_string` и `new_string` без изменений.
3. **Попытка обновить файл, который уже в желаемом состоянии**.

## Правила предотвращения

- **Перед `patch` проверяй актуальное содержимое файла** через `read_file`, если прошло много действий.
- **Если файл только что создан через `write_file`**, не делай последующий `patch` с тем же содержимым.
- **Если нужно убедиться**, что файл в нужном состоянии — используй `read_file` для проверки, а не `patch`.
- **Не используй `patch` как механизм проверки** — только для реальных изменений.

## Как отвечать пользователю

1. Объясни, что это не критичная ошибка.
2. Укажи, что файл уже находится в нужном состоянии.
3. Подтверди результат через `read_file` или `git status`, если нужно.

## Пример диалога

> Пользователь: "Что за ошибка? File-mutation verifier..."
>
> Агент: "Это шум от лишнего patch-вызова. Файл уже был создан правильно через write_file, поэтому второй patch с тем же содержимым не внёс изменений. Проверяю read_file — всё на месте."
