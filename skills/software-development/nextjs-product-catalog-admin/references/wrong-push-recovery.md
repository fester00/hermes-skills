# Восстановление при ошибочном пуше в неправильный репозиторий

## Проблема

Неправильно сделан `git push` в репозиторий `pentajunior` вместо `penta-junior-v2`.
Коммит с CRM-админкой попал в основной сайт вместо версии v2.

## Шаги восстановления

### 1. Откат последнего коммита в основном репозитории

```bash
cd /home/natan/workspace/pentajunior
git push origin HEAD~1:main --force-with-lease
```

Результат: `+ 4b69e69...e7e784c HEAD~1 -> main (forced update)`

**Важно:** `--force-with-lease` безопаснее чем `--force` — он отказывается,
если кто-то успел сделать push между вашим pull и force-push.

### 2. Копирование изменений в правильный репозиторий

```bash
cd ~/pentajunior-v2
# ... применить те же изменения через patch, write_file, или вручную ...
```

### 3. Commit и push в правильный репозиторий

```bash
git add -A
git commit -m "feat(crm): улучшенная темная CRM-админка"
git push origin master
```

## Уроки

1. **Всегда проверяй `git remote -v`** перед commit/push в проектах с похожими именами.
2. **Проверяй `git status --short`** после создания новых файлов (они не попадут
   в коммит автоматически).
3. **Не используй `write_file` для файлов > 2000 строк** если ранее читали их
   частично через `offset`/`limit` — это приводит к случайному truncation.
