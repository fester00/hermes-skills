# Сопоставление текущего товара с колонкой в сравнительной таблице (pentajunior-v2)

## Проблема

В `TableIncluder.tsx` текущая колонка определялась по последней части `productId`:

```tsx
const productMark = productId?.split('-').pop(); // "unisil-9331" → "9331"
```

Это работало для чисто цифровых марок (`9331`, `9145`), но ломалось для смешанных и буквенных марок, когда колонка в spec-таблице написана иначе, чем `productId`:

| Товар | `productId` | Колонка | Почему не совпадало |
|---|---|---|---|
| ЮниКаст 6В | `unicast-6v` | `6В` | латинская `v` vs кириллическая `В` |
| ЮниКаст Trans | `unicast-trans` | `TRANS` | регистр |
| Пента-200 | `penta-200` | `Пента®-200` | бренд-префикс + символ ® |

## Решение

Добавить функцию нормализации строк, которая:

1. приводит к нижнему регистру;
2. удаляет пробелы, дефисы, символы ®/™/©;
3. транслитерирует латинские буквы, похожие на кириллические (`a→а`, `b→б`, `v→в` и т.д.).

```tsx
const normalize = (str: string | null | undefined) => {
  if (!str) return '';
  return str
    .toLowerCase()
    .replace(/[\s\-®™©]/g, '')
    .replace(/[a-z]/g, (ch) => {
      const map: Record<string, string> = {
        a: 'а', b: 'б', c: 'ц', e: 'е', k: 'к', m: 'м',
        o: 'о', p: 'р', t: 'т', v: 'в', x: 'х', y: 'у',
      };
      return map[ch] ?? ch;
    });
};
```

Сравнение идёт в три этапа — от строгого к мягкому:

```tsx
const isCurrentProductColumn = (col: string) => {
  if (!productMark) return false;
  const suffix = productMark.toLowerCase();
  const normCol = normalize(col);
  const colNumber = col.match(/\d+/)?.[0] ?? null;

  // 1. Точное совпадение последнего сегмента заголовка колонки с маркой
  if (col.split('-').pop()?.toLowerCase() === suffix) return true;

  // 2. Нормализованное полное совпадение (кириллица/латиница/знаки)
  if (normCol === normProductMark) return true;

  // 3. Если у марки и колонки есть числа — сравнивать их целиком,
  //    чтобы 10 не совпадало с 100/1000, а 100 — с 1000.
  if (productNumber && colNumber) {
    return productNumber === colNumber;
  }

  // 4. Fallback: суффикс содержится в заголовке колонки (для немаркированных таблиц)
  return normCol.includes(suffix) ||
    (normalize(productTitle).includes(suffix) && normCol.includes(suffix));
};
```

## Проверка

Для всех товаров с `spec_table_id` из `pentajunior.db` проверить, что ровно одна колонка каждой таблицы выделяется как текущая. Для `unicast-xxx` это должны быть `6В`, `4`, `TRANS`. Для линейки `ПМС` обязательно проверить `ПМС-10`, `ПМС-100` и `ПМС-1000` — раньше из-за `includes('10')` подсвечивались все три.

## Подводные камни

- Не хардкодить список исключений (`if (id === 'unicast-trans') ...`). Количество таких случаев растёт.
- Не полагаться только на `productId.split('-').pop()` — в колонках могут быть бренд-префиксы (`Пента®-200`) или кириллические буквы (`6В`).
- Нормализация должна быть достаточно консервативной, чтобы не сопоставить две разные колонки случайно. Лучше недостаточно, чем избыточно.
- При добавлении новых spec-таблиц через админку стоит называть колонки так, чтобы они максимально совпадали с `productId` (или наоборот).
