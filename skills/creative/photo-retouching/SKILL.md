# Ретушь и замена фона на фото

Пользователь присылает фотографию и просит «сделать норм», «профессионально обработать» или «поменять фон». Задача — не применить фильтр, а пройти конвейер как ретушёр: разобрать кадр глазами, починить свет/тон/кожу, отделить объект от фона, отдать результат **вместе со сравнением до/после** и честным списком того, что не вытянуть.

## When to Use

- Портретная ретушь (кожа, блики, глаза, тон, кадрирование).
- Замена фона (ванная → водопад, стена → студия) и любые композиты.
- «Обработай как профессионал» — то же самое: тон, кожа, фон, грейд.
- Не для этого: генерация изображения с нуля (`comfyui`, `image_gen`), склейка документов, OCR.

## Инструменты и что где лежит

| Что | Чем |
|---|---|
| Портретная ретушь | `scripts/retouch_portrait.py` (OpenCV; проверенный конвейер: кожа, блики, глаза) |
| Художественная ретушь портрета (успокоить фон, split-tone, зерно) | `scripts/portrait_art.py` — параметры через `key=value`, `crop=x1,y1,x2,y2`, `bw=1` |
| Грейд кадра (интерьер, событие, группа) | `scripts/grade_scene.py` — из линейного RAW в готовый JPEG |
| Декод RAW (DNG/CR3/ARW) | `rawpy` (LibRaw): `pip install rawpy` |
| ИИ-вырезка объекта | PhotoCraft headless MCP: `select.subject` → `layer.new.layerViaCopy` → `doc_export` PNG с альфой |
| Композит | PIL (`Image.composite`) после вырезки |
| Грейд/ретушь внутри PhotoCraft | `scripts/pc_grade.py job.json` — открыть файл → шаги → сохранить → доп. шаги → второй файл (один процесс CLI) |
| Рисование с нуля в PhotoCraft | `scripts/pc_draw.py steps.json` — исполняет шаги генератора в чистом документе |
| Смотреть результат | `vision_analyze` на кропах 2–3× — только так видно артефакты |

Интерпретатор с OpenCV бери так: `PY=$(ls ~/.hermes/tools/python-3.14*/bin/python3.14 | head -1)`. Без `head -1` при двух установленных версиях глоб возвращает две строки, `"$PY"` становится невалидным путём — и скрипт падает с «no such file or directory» на пути с звёздочками.

Оба приложения ArtCraft (PhotoCraft, LightCraft) ставятся и подключаются по навыку `headless-desktop-apps` + `native-mcp`; GUI для ретуши не нужен, headless-режим справляется.

## Порядок работы

### 1. Сначала смотреть, потом трогать

`vision_analyze` на весь кадр с прямым вопросом: какой свет, где блики, что с кожей, что с балансом белого, что мешает в кадре (потолок, угол стены, тёмное пятно, лишние предметы). Решение о стратегии принимается по этому разбору, а не по шаблону.

### 2. Выбрать стратегию замены фона

- **Заменить только стену/фон, оставив объект и всё, что ниже линии опоры** (борт ванны, вода, пена) — так выглядит правдоподобно почти всегда.
- Полная вырезка человека на пейзаж — только если объект контрастный и без мелких полупрозрачных деталей. Пена, брызги, вода, развевающиеся волосы дают рваные края и ореолы; в таком случае честно сказать это и предложить вариант «заменить стену».

Рецепт композита с ИИ-маской и её ловушками: `references/background-swap.md`.

### 3. Ретушь портрета — конвейер

```bash
PY=<python с opencv>   # pip install opencv-python-headless
$PY scripts/retouch_portrait.py in.jpg out.jpg '{"crop":[50,330,910,1250]}'
# кроп лица 2× для контроля
$PY -c "from PIL import Image; im=Image.open('out.jpg'); im.crop((200,60,700,560)).resize((1000,1000)).save('face.jpg',quality=93)"
```

Порядок шагов (в скрипте он же): баланс белого по «серым» пикселям → тональная кривая в LAB → маска кожи по YCbCr → сглаживание с возвратом текстуры → гашение бликов по локальному превышению → глаза (белки, микроконтраст, искра) → фон (блюр, затемнение, обесцвечивание) → винъетка → резкость только вне кожи → чёрная точка и грейд → тепло кожи → финальное сжатие светов.

Рабочие значения для ровного комнатного света (плоский селфи-свет): `smooth 0.40`, `texture 0.50`, `shine 0.25`, `shaping 0`, `contrast 0.10`, `black 3`, `sat 1.05`, `vignette 0.20`, `hl_final 0.5`, `catchlight 18`, `skin_warm 3`.

Если исходник пришёл как RAW, работа начинается на шаг раньше: `rawpy` → 16 бит линейно → и только потом весь конвейер. Рецепт, порядок шагов в линейном пространстве, рабочие значения и ловушки: `references/raw-and-grading.md`.

### 3b. Ретушь внутри PhotoCraft (когда просят «через PhotoCraft»)

PhotoCraft headless-MCP умеет всё нужное без GUI: это 940 команд движка (`command_list` отдаёт у каждой поле `params` — читать его, а не угадывать), запуск через `command_batch {steps:[{id,params}],stop_on_error:false}` — один round trip на весь проход.

Рабочий конвейер (проверен на портрете 960×1280):

1. `doc_open {path}` → `doc_inspect` (размер, слои).
2. Шумодав: `filter.noise.median {radius:1}` → `filter.blur.surfaceBlur {radius:2,threshold:12}`. Тени-шум падает 0.74 → 0.47 без пластика; сильнее `radius` — уже «воск».
3. Точечная ретушь: `paint.spotHealing {points:[[x,y]],size,hardness:65,type:"contentAware"}` — по одному вызову на пятно (несколько точек в одном `points` дают мазок-дорожку). Для крупных объектов — `paint.remove {strokes,closeLoops:true}`, он на background-job.
4. Грейд: `image.adjustments.levels {inBlack,gamma,inWhite}` → `curves {points:[[0,3],[48,50],[128,134],[192,196],[255,250]]}` → `hueSaturation {yellows:{saturation:-9},reds:{saturation:-4}}` → `vibrance {vibrance:10,saturation:-3}`.
5. Отделение от фона: `select.subject` → `select.inverse` → `levels {outWhite:235}` (притемнить) и/или `hueSaturation {saturation:-34}` (успокоить цвет) → `select.deselect`. Маска ИИ возвращает `bounds` — сверить, что она не съела объект.
6. Резкость последней, с порогом: `filter.sharpen.unsharpMask {amount:32,radius:0.8,threshold:4}` — без порога шумодав возвращается шумом.
7. `doc_save {path,format:"jpg",quality:97}`; замер шума и `vision_analyze` по кропу 12× — до отдачи.

Питфоллы PhotoCraft:

- **Команды `filter.*` и `paint.*` пишут в активный слой** и отвечают `{"layer":N}`; `paint.spotHealing` отвечает `{"damage":[x,y,w,h]}` — по этому bbox видно, куда реально попала кисть.
- **Координаты пятен искать глазами, а не автодетектом.** Автопоиск «крошек» по контрасту и красноте даёт десятки ложных срабатываний на губах, складках и волосах. Надёжно: кроп 5–12× с сеткой каждые 5 px и подписями координат полного кадра → прочитать точки глазами → `vision_analyze` на увеличенный участок, чтобы подтвердить.
- В PhotoCraft есть **`filter.noise.reduceNoise`** (`strength`, `preserveDetails`, `removeJpegArtifact`) — он именно убирает шум и артефакты JPEG, а не наоборот. Для маленьких сжатых исходников это лучше, чем `median`/`surfaceBlur`: пара `reduceNoise{strength:4,preserveDetails:80,removeJpegArtifact:true}` + `unsharpMask{amount:30,radius:3,threshold:6}` даёт чистые тени без пластика (проверено на грейде 4000×6000).
- Винъетки отдельной командой нет (`gradient.fill.create` или маска + curves). А `filter.noise.addNoise`, `filter.gallery.grain`, `filter.gallery.filmGrain` есть — их не вызывать, если просили «без шумов»: соблазн «добавить фактуру» здесь и приводит к вопросу «почему появился шум».
- **`select.subject` работает headless**, GUI не нужен; но после каждого прохода возвращать `select.deselect`, иначе следующая команда сработает внутри старой маски.

### 3c. Рисование с нуля в PhotoCraft (постер, иллюстрация, эмблема)

PhotoCraft умеет рисовать: `shape.create` (rect/roundedRect/ellipse/polygon/star/line/path), `path.set` + `path.fill`/`path.stroke`, `paint.stroke`, `gradient.fill.create`, `type.create`. Рабочий подход — **параметрический генератор в Python**: скрипт считает координаты (дуги через `arc_pts`, шестиугольники, силуэты гор) и пишет `steps.json`, а `pc_draw.py` исполняет его в CLI одним процессом. Итерации — перезапуск скрипта с правками, как сборка.

Питфоллы (стоили восьми итераций на постере «Мастер Угвей»):

- **Альфа в заливке `[r,g,b,a]` — доля 0..1, не 0..255.** С `round(a * 255)` все полупрозрачные ореолы становятся непрозрачными и заливают кадр белыми пятнами. Симптом: вместо свечения — огромный светлый круг.
- **MCP-сервер требует строгой последовательности.** `initialize` первым, ответ дождаться, потом `notifications/initialized`, и только затем по одному вызову с ожиданием ответа по `id`. Если отправить пачку строк сразу — первые команды падают `"no document open"`, а отправка `initialized` до `initialize` роняет процесс (BrokenPipe).
- **`doc_new` принимает `mode: "rgb"` (строчными) и `background: "white"`**, а не `mode:"RGB"`/`fill` — иначе «no document open» на всём дальнейшем.
- **Безье в `path` через `in`/`out` даёт непредсказуемый результат** (самопересечения, нулевая площадь, фигура исчезает). Для иллюстраций безопаснее полигоны с большим числом точек по дуге: `arc_pts(cx,cy,rx,ry,a0,a1,n)` → купол панциря, дуги, волны.
- **Не рисуй мягкий свет наложением колец-эллипсов с малой альфой** — получаются видимые концентрические полосы. Мягкое гало = `select.rect {ellipse:true, feather}` + `gradient.fill.create {style:"radial", transparency:[[0,60],[0.5,20],[1,0]]}` + `select.deselect`.
- **Полосы тумана полигонами с альфой 0.15–0.2 читаются как снежные вершины с жёстким краем.** Если нужен туман — альфа 0.05–0.08 и несколько слоёв; либо не рисовать вовсе.
- **Фигура должна быть ПЕРЕД землёй, а не за ней.** Если утёс нарисован после фигуры — ноги уходят под землю и персонаж «утоплен». Порядок: небо → дальние планы → земля → фигура → детали.
- **Замеряй композицию числами, а не «на глаз»:** масштаб фигуры к кадру (у меня 33 % высоты — читается), луна ≤ 15 % ширины, текст в спокойной тёмной зоне ≥ 15 % от низа. Без этого первый вариант даёт луну в полкадра и фигуру-точку.
- **Всегда проверять рендер зрением на каждом шаге** (`doc_save` → `vision_analyze`): команды отвечают `null` на успех, а глазами видно только после экспорта.

Честная граница: геометрия, плакат, схема, инфографика, типографика — получается за 2–4 итерации; «живописная рука» (свободные мазки, характер) — нет, нужен десяток итераций и всё равно будет наивно. Говорить это пользователю прямо, а не выдавать за живопись.

### 3d. Грейд под присланный референс («сделай в таком стиле»)

Когда пользователь даёт своё фото + ссылку на чужой кадр «в таком стиле»:

1. Скачать референс (`curl` с User-Agent и `Referer` — CDN-превью без них отдаёт 403/пусто) и **разобрать его зрением**: палитра светов, теней и кожи, где контраст на кривой, как распределена насыщенность, есть ли зерно, ч/б или цвет. «Тёплый editorial» — не параметр; нужны числа и названия команд.
2. Перевести разбор в команды PhotoCraft и применить к исходнику того же жанра.
3. **Замерять клип ПОСЛЕ грейда, а не до:** `(g>=250).mean()*100` и `(g<=5).mean()*100` по 8-битной серой копии. Первый проход по editorial-референсу дал 7.26 % выжженных пикселей — белое пальто на солнце потеряло ткань; лечится `levels {outWhite:245}` + `shadowsHighlights {highlightAmount:18}`, после чего 0.52 %.
4. Основным файлом отдавать **чистую версию**, зерно — только если оно есть в референсе и только отдельным файлом: пользователь, который однажды просил «без шумов», grain в основном файле воспримет как порчу кадра.

Ч/б editorial как отправная точка (JPEG 4000×6000): `image.adjustments.blackWhite {reds:70, yellows:95, greens:40, cyans:55, blues:22, magentas:45}` (поднятые жёлтые и красные держат кожу светлой и отделяют её от серого трикотажа) → `levels {inBlack:5, gamma:1.02, inWhite:250, outWhite:245}` → `curves {points:[[0,0],[30,21],[76,71],[128,132],[188,192],[234,234],[255,244]]}` → `shadowsHighlights {shadowAmount:12, highlightAmount:18}` → `brightnessContrast {brightness:2, contrast:12}` → `unsharpMask {amount:55, radius:1.2, threshold:3}`. Второй файл того же кадра — `filter.gallery.filmGrain {grain:3}`.

Исполнитель — `scripts/pc_grade.py job.json`: один процесс CLI, `doc_open` → `steps` → сохранить → `then_steps` → второй файл. Он же годится для любого покадрового грейда без GUI; рисовальщик — `scripts/pc_draw.py`.

### 4. Смотреть и переделывать

Каждая итерация заканчивается просмотром: полный кадр + кроп лица 2–3×. Правки — по одному параметру, а не «сделать всё сильнее». Обычно 2–4 итерации. Что искать: пересвеченные пятна с резкой границей, пятнистость на щеках и шее, пластиковость, потеря текстуры, ореолы по краю объекта.

### 5. Отдать

- Результат + **сравнение до/после** одним файлом (склейка двух кропов в один JPEG) — по одному кадру разницу не оценить.
- **Исходник просить файлом, не «фото».** Telegram пережимает картинки до 1280 px по длинной стороне и режет EXIF: фото 960×1280 в чате — это уже не оригинал телефона. Ретушь по сжатой копии не вытянет детали, и это надо сказать вслух.
- **Отдавать тоже файлом.** `MEDIA:` в чате шлёт изображение как фото → опять сжатие; для полного качества — `scripts/tg-send.py <алиас> "подпись" файл --doc` из навыка `hermes-internal-operations` (Bot API sendDocument).
- **Документ в чат упирается в 20 МБ.** Публичный Bot API не даёт скачать/принять больше 20 МБ — это не сбой отправки, а `getFile`-лимит; файл больше просто не доедет ни как фото, ни как документ. Проверяй размер: 24 МП JPEG в качестве 95 — обычно 12–18 МБ и проходит, а RAW/TIFF — нет. Для тяжёлого оригинала или результата — облако: Яндес.Диск (`scripts/disk-exchange.py put` из навыка `yandex-api` либо `scripts/ya-upload.py <файл> <путь на диске>`, токен `YANDEX_DISK_TOKEN` в `.env`) и ссылка/путь в ответе. Забирать оттуда тоже удобнее: API отдаёт полный файл без лимитов чата.
- **Рабочий набор вариантов — три, с номером в подписи.** Цвет полным кадром → кроп плотнее по лицу (4:5, объект крупнее, края беспорядка за кадром) → ч/б с усиленным зерном. Подписи вида «1/3 — цвет, полный кадр», «2/3 — кроп 4:5», «3/3 — ч/б» — иначе «второй лучше» без якоря. В ответе сказать, какой считаешь сильнейшим, но выбор оставить за ним.
- **Одну версию — один файл.** Если отдаёшь несколько вариантов, подписывай каждый (`v3`, `v5`, `v7`) в отдельном сообщении файлом: без подписи пользователь говорит «третий лучше» и приходится угадывать, что он считал.
- **Рабочие копии — на мусор, пайплайн — на память.** После выдачи (особенно по просьбе «удали эти фото») чисти промежуточные `v1…vN`, кропы и исходники в `tmp/`, но скрипт конвейера и подобранные параметры оставляй: следующее фото пройдёт без круга «блик → пятна → пластик».
- Пути в долговременное место (`/mnt/data/natan-storage/photos/`), не в `tmp/` — временная папка чистится.
- В ответе: что сделано по шагам, какие параметры крутились, **что синтезировано** (усиленный блик в зрачке, дорисованные детали) и что не вытянуть из исходника (плоский свет, жёсткий блик лба). Предложить конкретные варианты: теплее/холоднее, убрать искру, ч/б, тяжелее кожа.

## Питфоллы (стоили итераций)

- **Порог по яркости для гашения блика даёт «диск» с видимой кромкой.** Считать не порог, а превышение над локальным средним: `spec = L - GaussianBlur(L, sigma=38)`, затем `L -= k * max(spec,0) * skin`. Множитель 0.25–0.6, края нет вообще.
- **`shaping`/clarity по маске кожи раздувает блики в пятна.** Среднечастотный контраст на коже держать 0 (или до 0.1): он поднимает не только форму, но и зеркальные пятна, и после кривой они выглядят «электрическими».
- **Возврат текстуры больше 60% возвращает и блики.** После билатерального сглаживания подмешивать высокие частоты на 40–55% — компромисс между «поры видны» и «кожа воск».
- **Финальное сжатие светов обязательно.** Даже после гашения блика верхние 10–15% яркости нужно мягко поджать: `L -= 0.45 * max(L-0.82, 0)` в самом конце, иначе лоб и нос выжигаются грейдом.
- **Маска кожи течёт на одежду и фон.** Оставлять связную компоненту максимальной площади + морфология; иначе «грязные» пятна уходят в свитер и стены.
- **Глаза искать по тёмным пятнам, а не «по центру».** Два крупнейших тёмных blob’а в средней трети кадра → эллипсы → в них белки светлее, микроконтраст, искра по 92-му процентилю. Без этого взгляд остаётся мёртвым.
- **Кадрирование — половина «профессиональности».** Убрать потолок, угловую линию, тёмное пятно в углу; оставить воздух над головой. Кадр с пустой стеной сверху читается как «фото на телефон».
- **Сравнение до/после строить на одинаковом кропе.** Разный масштаб в склейке — сравнение ни о чём.
- **Цветовые каналы: RAW-декодер отдаёт RGB, OpenCV ждёт BGR.** Если после декода в цепочке стоит `cv2.cvtColor(img, COLOR_BGR2LAB)`, красное платье станет синим, а кожа — зеленоватой. Один `img = cv2.cvtColor(img, cv2.COLOR_RGB2BGR)` сразу после перевода в 8 бит, до любых LAB/HSV-операций.
- **Шум на 100% у 24 МП в помещении — норма, а не брак обработки.** Не гонись за чистотой пикселя: оценивай на размере просмотра и в печати, иначе шумодав съест волосы и ткань. Просить файл, а не сжатое фото, стоит ради деталей и запаса в светах, а не ради «стерильности».

- **Авторский лук — на чистый рендер, а не на готовый JPEG.** Второй проход контраста/клирити/зерна поверх уже обработанного и зашарпленного файла усиливает шум и срезает насыщенные красные. Когда просят «обработать как фотограф» после технического грейда — рендери каждый вариант заново из RAW с другими параметрами лука (`warm/cool`, `halation`, `grain`, `desat_high`), по одному запуску на вариант.
- **Зерно задаётся на пиксель, а не на кадр — масштабируй его по размеру картинки.** Одно и то же `grain 2.4` на 24 МП (6012×4008) невидимо, а на 960×1280 бьёт в глаза: площадь меньше в 20 раз, крупинки крупнее во столько же. Считай амплитуду как `grain * (min(W,H)/1280)` (в `scripts/portrait_art.py` это `grain_scale`), а ниже ~1600 px по короткой стороне зерно вообще выключай. Иначе пользователь спрашивает «почему появился шум, раньше его не было» — и он прав.
- **Любая добавленная фактура — синтетика, говори о ней до выдачи.** Зерно, галация, подъём теней и клирити вытаскивают компрессионную кашу маленького JPEG; без предупреждения это читается как «испортил фото». В ответе — одной строкой: что добавлено намеренно и что из этого убирается по слову.
- **Спор о шуме решается замером, а не на глаз.** Высокочастотная составляющая (`g - GaussianBlur(g, 1.2)`) по плоским участкам теней (`|Sobel| < 12` и `g < p35`) даёт число: исходник 0.74, с зерном 2.4 — 3.50, без зерна — 0.62. С этими цифрами видно, что «шум» — твоё зерно, а чистый вариант тише оригинала (билитерал по коже заодно снял JPEG-кашу).
- **На жалобу про шум отдавай две версии сразу — `grain=0` и половинную.** Чистая как основная рекомендация, половинная как компромисс «фактура без грязи»; спрашивать «какое зерно ты хочешь» бессмысленно — человек его не заказывал. Красный платьев и гирлянд уходит в 255 и теряет ткань; перед грейдом держи мягкое колено по максимуму канала (`x *= (knee/max)^s` при `max > knee`) — иначе на превью видна «залитая» площадь вместо складок.

## Что не делать

- Не описывать словами «я бы поправил» вместо результата: сначала файл, потом пояснение.
- Не выдавать синтетику за съёмку: усиленный блик в зрачке, дорисованный фон, искусственное размытие фона — назвать в ответе.
- Не убирать тени под глазами и носогубные складки «в ноль» — лицо становится маской; поднимать тени на 10–15 единиц L, не больше.
