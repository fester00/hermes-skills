# Короткое видео из фото: рилс, шортс, слайд-шоу

Пользователь просит «сделать рилс из нескольких фото, добавить музыку и надписи, секунд на 10». Класс работы: собрать вертикальный ролик из статики, озвучить, отитровать и отдать файлом. Задача не в «склеить кадры», а в ритме: длительность на фото, переходы, безопасные зоны под интерфейс соцсети, музыка с фейдами.

## When to Use

- Ролик из фото/скриншотов/кадров с музыкой и титрами, вертикаль 9:16.
- Нарезка готового видео, переозвучка, экспорт под площадку — тот же движок (FilmCraft).
- Не для этого: генерация видео моделью (это ArtCraft Studio, не одна из 13 craft-приложений), анимация математики (`manim-video`).

## Сначала выясни входы, потом собирай

Четыре вопроса — без них ролик не собрать: **какие фото** (сколько, в каком порядке), **музыка** (готовый трек или генерировать), **текст надписей**, **длина и формат**. Не придумывай надписи, если пользователь сказал «текст напишу сам»: он пришлёт следующим сообщением, а переделка титров — это пересборка всего таймлайна.

Пока ждёшь фото — сгенерируй музыку и проверь движок, чтобы потом собрать за один проход.

## Установка FilmCraft (без sudo)

`FilmCraft` — нелинейный видеоредактор из серии ArtCraft, свои кодеки (H.264/HEVC/ProRes/AAC), GPU-композитор, headless-CLI с MCP-мостом.

```bash
export PATH="$HOME/.nvm/versions/node/v24.13.1/bin:$PATH"
cd /mnt/data/artcraft/dl
gh release download v<version> --repo storytold/filmcraft \
  --pattern "filmcraft-<version>-linux-x86_64.deb" --pattern "SHA256SUMS.txt" --clobber
sha256sum -c <(grep 'filmcraft-.*linux-x86_64.deb' SHA256SUMS.txt)   # сверить, не пропускать
dpkg-deb -x filmcraft-<version>-linux-x86_64.deb /mnt/data/artcraft/filmcraft
/mnt/data/artcraft/filmcraft/usr/bin/filmcraft-cli --version
```

Версию брать из `gh release view --repo storytold/filmcraft`, а не из памяти: приложения серии выпускаются пачками. GitHub API без токена отдаёт `rate limit exceeded` — запросы про релизы делать через `gh`, а не голым `curl` к api.github.com.

## Сборка ролика через CLI

Список и параметры команд берутся с самого бинаря, не из документации:

```bash
CLI=/mnt/data/artcraft/filmcraft/usr/bin/filmcraft-cli
$CLI commands --json > /tmp/fc.json      # все команды
$CLI describe clip.automateToSequence    # параметры конкретной
$CLI run script.jsonl                    # последовательность: один {"id","params"} на строку
```

Порядок работы:

1. `file.newProject {name}` → `file.newSequence {name,width:1080,height:1920,fps:30}` — вертикаль задаётся здесь, не кропом при экспорте.
2. `file.import {paths:[...]}` — фото и музыка в проект (или `$CLI import <file>...`).
3. **`clip.automateToSequence`** — сборка слайд-шоу одним вызовом: `{items:[id...], ordering:"sort", placement:"sequentially", method:"overwrite", stillFrames:N, overlapFrames:M, videoTransition:true}`. `stillFrames` — сколько кадров держать каждое фото, `overlapFrames` — нахлёст под кроссфейд.
4. `graphics.newText {text, box:[w,h], position:[x,y], font, size, seconds}` — титры. Позиция в нижней трети: верхние ~14 % и нижние ~20 % кадра перекрываются интерфейсом Reels/TikTok, туда ничего не ставить.
5. `effects.addKeyframe` / `effects.setKeyframe` — «оживление» статики (медленный scale 1.0→1.06 или сдвиг position). Без кейфреймов слайд-шоу читается как презентация.
6. `clip.audioGain` + `sequence.applyAudioTransition` — музыка с фейдами; дорожку обрезать по длине секвенции, а не наоборот.
7. `$CLI export out.mp4 --format h264 --settings '<json>'` (или `--preset`); затем проверить `ffprobe` — кодек, разрешение, fps, длительность, наличие аудиопотока.

Рендер проверять своим замером, а не сообщением инструмента: `ffprobe -v error -show_entries stream=codec_name,width,height,r_frame_rate,duration -of json out.mp4`.

## Проверенный рецепт сборки (FilmCraft 0.15.0, headless)

Сценарий целиком — одним вызовом `run script.jsonl`, иначе состояние проекта не переносится между вызовами:

```jsonl
{"id":"file.newProject","params":{"name":"reels"}}
{"id":"file.newSequence","params":{"name":"Reels","width":1080,"height":1920,"fps":30}}
{"id":"file.import","params":{"paths":["…/still_01.jpg","…"]}}      # → {"items":[8,9,…]}
{"id":"project.select","params":{"items":[8,9]}}                     # без этого automate падает
{"id":"clip.automateToSequence","params":{"ordering":"sort","placement":"sequentially","method":"overwrite","stillFrames":100,"overlapFrames":12,"videoTransition":true,"ignoreAudio":true}}
{"id":"file.exportMedia","params":{"path":"…/out/reels.mp4","format":"h264","bitrateKbps":6000,"audio":true}}
```

Замеры смоука: 2 фото × 60 кадров с `overlapFrames:12` дали 108 кадров (3.6 с), рендер 18 fps — на 20 секунд уходит ~40 с.

### Грабли FilmCraft (ловил агент, воспроизводится)

- **`timeline.place` считает `time`/`duration` в тиках, а не в секундах** (`5` = один кадр). Передавать `{"seconds": N}` — либо пересчитывать в тики.
- **`timeline.place` на одной дорожке перезаписывает и разрывает уже положенные клипы** — силуэты и надписи разводить по разным дорожкам или укладывать строго последовательно.
- **`graphics.newText` `track` — индекс с нуля** (`track:3` = Video 4-я). Ошибка на единицу кладёт титры не туда.
- **`effects.setKeyframe` только редактирует существующий кейфрейм** («no keyframe at that time») — создавать пару `effects.setParam` с `keyframes`/`effects.addKeyframe`, потом править.
- **Битрейт → размер.** 12 Мбит/с на 20 с даёт ~30 МБ и не пролезет в Telegram (лимит 20 МБ). Считать так: `MB ≈ kbps × секунды / 8000`; для 20 с безопасно 5–6 Мбит/с.
- **`graphics.newFromFile` бесполезен в статическом JSONL**: id созданного слоя нельзя подставить в следующие строки. PNG-оверлеи класть через `file.import` + `source.overwrite` на отдельную дорожку.
- **Ассеты для анимации рисовать кодом** (PIL): паук, призрак, жук, мышь, паутина, тыква, искры, виньетка, полоса тумана — 512×512 PNG с альфой плюс полноэкранная виньетка 1080×1920. Силуэты делать крупными (14–22 % ширины) и со светлой обводкой: тонкие чёрные теряются на тёмном фоне. Рисовать в 4× и уменьшать — иначе рваные края.
- **Арифметика координат в PIL:** если центр задан уже умноженным на масштаб, а смещения умножаются ещё раз — фигура уезжает за холст и файл выходит пустым. Проверять bounding box непрозрачных пикселей после генерации, а не только факт сохранения файла.

## Надписи: стиль — часть задачи, а не украшение

Пользователь считает одинаковый шрифт с обводкой на всех кадрах «недоделанным» и просит «сделать надписи стилизованными». Сразу закладывать систему, а не один стиль:

- **Палитра из 4–5 цветов на весь ролик**, а не произвольный цвет на кадр: оранжевый, фиолетовый, кремовый, тёмный контурный, тёплый жёлтый.
- **Варьировать начертание и регистр**: часть кадров — КАПС крупно и жирно (ударные фразы), часть — строчными курсивом (лирические). Два шрифта на ролик достаточно; проверять, что у обоих есть кириллица (`fc-list :lang=ru family`).
- **Наклон ±1,5–2° и разный размер (72–80 px при ширине 1080)** — без этого надписи выглядят как субтитры из авторедактора.
- **Плашка под текстом** нужна там, где фон пёстрый и контраст текста низкий: полупрозрачный прямоугольник 40–50 %.
- **Пульс 100 → 103 → 100** за время жизни надписи: статичная типографика на живой анимации читается как брак.
- Смена текста: появление 6–8 кадров, уход 4 кадра. **Надпись обязана уйти за 4–6 кадров до склейки** и следующая — не раньше чем через 6–8 кадров после неё, иначе на кроссфейде две надписи читаются одновременно «в кашу».

**Позиция — по кадру, а не по шаблону.** Единый y для всех кадров ложится на лицо, когда ребёнок/человек в центре: на кадрах с крупным лицом поднимать надпись в коридор 35–45 % высоты, на общих планах — оставлять 60–72 %. Проверять по кадрам, а не по координатам в сценарии.

## Проверка рендера: три пробы

1. `ffprobe` — кодек, 1080×1920, fps, кадры, длительность, наличие аудиопотока; размер файла.
2. `ffmpeg -v error -i out.mp4 -f null -` — полное декодирование без ошибок (битый поток видно только так).
3. **Кадры на стыках: ±0,2 с от каждого перехода** (`ffmpeg -ss <t> -frames:v 1`) и один монтаж из них — только там видно наложение двух надписей и потерянный текст; `ffprobe` этого не покажет.

## Делегирование агенту

Сборку можно отдать внешнему агенту (opencode + модель пользователя), и это работает быстрее, чем делать всё самому, **но только при трёх условиях**: ассеты (фото, музыка, PNG-силуэты) готовит агент-оркестратор; в брифе лежит уже проверенный сценарий команд, а не ссылка на документацию; в брифе есть численные критерии приёмки, лимит итераций и запрет на самодельные оптимизаторы. Шаблон брифа — `templates/delegation-brief.md` в навыке `opencode-v2-cli`.

Файл отдавать пользователю сразу, как только он валиден по замерам, не дожидаясь финального отчёта агента: агент ещё может полчаса дописывать вывод, а результат уже готов.

## Музыка: генерировать, а не искать

Готового генератора музыки в окружении нет, поэтому инструментал синтезируется кодом: `scripts/generate_music.py` (пэды, бас, бочка, хэты, колокольчик по пентатонике; 48 кГц стерео WAV).

```bash
PY=$(ls ~/.hermes/tools/python-3.14*/bin/python3.14 | head -1)   # head -1 обязателен: при двух версиях глоб отдаёт две строки
"$PY" scripts/generate_music.py out.wav 10.5 92
ffmpeg -y -i out.wav -codec:a libmp3lame -b:a 192k out.mp3        # дать послушать до сборки
```

Три замера, без которых трек бракуется (каждый реально ловил брак):

- **Громкость.** Цель — RMS −14…−10 dBFS, пик не выше −1 dBFS. Простой gain не доводит тихий микс до цели: поднятие на нужные +4…+6 dB упирается в пик и клиппит. Рабочая связка — `ffmpeg -af "volume=6dB,alimiter=limit=0.94:attack=5:release=60"`, затем перезамер через декод в память. И не применять gain дважды (две по −1,5 dB подряд дали −17 dBFS — тихо).
- **Настроение по умолчанию — весёлое.** Для семейного/праздничного контента мрачный готический трек пользователь почти наверняка попросит переделать «повеселее». Сразу писать второй вариант: 112–120 BPM, пиццикато-бас «прогулкой», мелодия ксилофоном/челестой с синкопами, шейкер на шестнадцатых, лёгкий бит. Тёмный дрон с сердцебиением держать как альтернативу, а не как основу.
- **Баланс спектра.** Доли считать от суммы энергии в полосе 20–20000 Гц, а не от среднего по всему спектру — иначе получаются «2691 % энергии в низе». Ориентир живого трека: низ 4–8 %, низ-середина 30–45 %, середина 20–35 %, верх 8–15 %, воздух 10–20 %. Если низ в сотни процентов, а верх в единицах — трек бубнит: поднимать хэты и колокольчик, добавлять нефильтрованный подмес пилы в пэды.
- **Ширина стерео.** Корреляция каналов 1.0 = моно, для соцсетей плохо. Рабочий диапазон 0.3–0.6: Haas-сдвиг 8–12 мс на одном канале пэдов, разное панорамирование хэтов, разные наборы тапов реверба в L и R.

Синтез без сэмплов и без вокала — нормально для соцсетей; сказать пользователю прямо, что музыка синтезирована, и предложить заменить его треком.

## Отдача

- Файлом, не ссылкой: `scripts/tg-send.py <алиас> "подпись" out.mp4` (из навыка `hermes-internal-operations`). До 20 МБ — лимит Bot API; 10-секундный 1080×1920 H.264 обычно 2–6 МБ и проходит, длинный ролик — через облако.
- Музыку отправлять **до** сборки на прослушивание: переделать трек дешевле, чем пересобрать таймлайн.
- В ответе: длительность, разрешение, fps, кодек, что за музыка (синтез), где титры и что можно поправить (темп, длина кадра, другой трек).

## Питфоллы

- **`$CLI commands --json | python` в одной строке теряет пайп**: интерпретатор в переменной после `|` не подставляется, команда падает `: command not found`. Сначала сохранить JSON в файл, потом читать его питоном.
- **Автосборка по `sort` берёт элементы в порядке проекта, а не в порядке присланных файлов.** Порядок кадров задавать через `items` явно, если он важен для истории.
- **`ffprobe`/`ffmpeg` в системе есть, внутри FilmCraft — нет.** Конвертацию mp3↔wav, замеры и превью делать системным ffmpeg, а не искать внутри движка.
- **FilmCraft — отдельная серия приложений ArtCraft; PhotoCraft/LightCraft видео не умеют.** Задача «сгенерировать видео, которого не было на съёмке» — это ArtCraft Studio, а не craft-приложение.
- **Титры и музыка — часть таймлайна, а не пост-обработка.** Поменять текст после рендера = пересобрать; поэтому текст утверждается до сборки.
- Проверять результат `vision_analyze` по кадрам-превью, а не только `ffprobe`: метаданные скажут «h264 1080×1920», но не скажут, что титр уехал под интерфейс.
