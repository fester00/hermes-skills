# Рецепт: SEO-проход по одной категории pentajunior-v2

Рабочий паттерн, выработанный в сессиях по всем 13 категориям проекта.

## Принципы

- Работаем **по одной категории за раз**: категория → подкатегории → товары.
- Для SEO-источника используем **только `yandex-seo-optimization`** (явное требование пользователя).
- `pentajunior-v2-seo` — проектный workflow: SQLite-аудит, build gate, JSON-LD, git, deploy.
- **Title ≤70 символов, description 160–170 символов (включая пробелы).** Диапазон 160–170 согласован с пользователем для pentajunior-v2; ≤160 — старый лимит, применяется только если явно сказано.
- **Keywords** — по формуле: `марка` + `тип/термин` + `целевое применение 1` + `целевое применение 2` + `коммерческий/общий термин`.
- **Технические характеристики** (Шор, сСт, диаметры в мм) — в карточку товара, не в keywords.
- **Пищевая/медицинская промышленность** — прямые упоминания только у продуктов, которым это свойственно. На момент сессий единственный такой продукт — **ТСМ-1**.
- **«От производителя»** убираем, если компания не производит. Заменяем на «купить» / «в Москве» / «официальный дистрибьютор ООО «ТЕХГРАНТ»» (для ТЕХМОЛ).
- **Ориентир в keywords — название товара (марка), а не ID.** Например, товар с ID `-9240` называется «Юнисил 9240» — используем «Юнисил 9240».

   ```python
       print(e['id'], len(e['meta_title']), e['meta_title'])

       print(e['id'], len(e['meta_description']), e['meta_description'])
   ```
5. **Проверить проблемы:**
   - длина `meta_title` > 70;
   - длина `meta_description` > 170;
   - **слишком короткие title/description** — дорабатывать, если есть запас до лимита (title <50–55, description <130–140);
   - упоминание **цены** (`от 590 ₽/кг`, `цена от`, `₽/шт`) в `meta_description` — запрещено;
   - упоминание **«материал дышит»**, **«кожа дышит»**, **«разведение»**, **«разводится»** — заменять;
   - упоминание «от производителя» или «производитель» в конце;
   - упоминания пищевой/медицинской отрасли (кроме ТСМ-1);
   - одинаковые наборы keywords у товаров;
   - технические спецификации в keywords.
4. **Составить черновик** для категории, подкатегорий и товаров.
5. **Показать черновик пользователю**, получить «давай».
6. **Применить UPDATE через Python `sqlite3`.**
7. **Build gate:**
   ```bash
   cd /home/natan/pentajunior-v2
   ./node_modules/.bin/tsc --noEmit
   rm -rf .next tsconfig.tsbuildinfo
   npm run build
   ```
8. **git add pentajunior.db**, commit, push.
9. **Сообщить:** «Изменения запушены. Деплой не делаю без твоего разрешения — скажи «задеплой», когда будешь готов». Ждать именно команду «задеплой».

## Подводные камни массовых проходов

- Усиление одних страниц может «выдавить» другие за лимит: после каждой итерации перепроверять `LENGTH(meta_title) > 70` и `LENGTH(meta_description) > 160` по всем сущностям, а не только по изменённым.
- Часто превышают лимит категории и подкатегории, потому что в них хочется вместить больше марок.
- Если title/description категории получается >70/>160 — сокращать через удаление брендового суффикса или обобщение, а не через срезание применения.
- После массового расширения description у товаров проверить, что `page_description` тоже ≤160, если его трогали.
