# Desktop-приложения на headless Linux

## When to Use

- Нужно поставить на сервер GUI-приложение (редактор, плеер, CAD, IDE, креативный тул) и потом работать с ним из агента.
- Сервер без монитора, `sudo` требует пароль, корень `/` мал или занят.
- Нужна локальная копия документации продукта без выкачивания всего репозитория.
- Скип: приложение уже стоит в системе, или задача — только браузерный логин (`headful-browser-server`).
Сервер без монитора, `sudo` требует пароль, корень `/` маленький — всё это решается без установки
в систему и без рута.

## 1. Найди правильный артефакт, а не первый попавшийся

Релизы почти всегда содержат отдельные сборки по платформам и часто **отдельный CLI-артефакт**
(`*-cli-<ver>-<os>.zip`) — его наличие само по себе говорит, что приложение управляется
программно, а не только мышью.

```bash
curl -sS "https://api.github.com/repos/<owner>/<repo>/releases/latest" \
  | python3 -c "import json,sys;d=json.load(sys.stdin);print(d['tag_name']);[print(' ',a['name'],a['size']//1024,'KB') for a in d['assets']]"
```

Убедись, что в списке есть linux-x86_64 (или твоя архитектура): `uname -m`.
Суммы сверяй по `SHA256SUMS.txt` релиза. **Сравнивай только поле хеша:** строки в файле имеют вид
`<hash>  <filename>`, и `grep | awk '{print $1}'` легко возвращает `file.txt:<hash>` — тогда проверка
печатает FAIL на верном файле.

## 2. Ставь без root и мимо маленького корня

На headless-хосте GUI-бинари по 70–120 МБ каждый; если `/` забит, ставить некуда — клади на большой
volume (`/mnt/data/...`) и держи версию в пути.

```bash
df -h / /mnt/data                 # куда влезет
mkdir -p /mnt/data/<app> && dpkg-deb -x app_<ver>_amd64.deb /mnt/data/<app>
ls /mnt/data/<app>/usr/bin        # GUI + *-cli рядом
```

`dpkg-deb -x` не требует рута и не регистрирует пакет — обновление это просто новая распаковка в
новую папку. AppImage: `./App.AppImage --appimage-extract` (или прямо запуск, если есть `/dev/fuse`).
tar.gz — просто распаковать. Системный путь (`/usr/bin`) нужен только если без него не находится
бинарь; абсолютный путь в конфиге клиента решает ту же задачу без рута.

Сразу проверь запуск — до любых настроек:

```bash
/mnt/data/<app>/usr/bin/<app>-cli --version
```

## 3. GUI на виртуальном дисплее

Приложение без `$DISPLAY` падает с `Missing X server or $DISPLAY` — это не поломка пакета.
Поднимай Xvfb и веди окно через VNC/noVNC; готовый рецепт и launcher: `headful-browser-server`
(Xvfb `:42` + `x11vnc` на localhost + `websockify`/noVNC).

- Процессы, запущенные из сессии, **умирают при рестарте гейтвея** — после рестарта стек (Xvfb, GUI,
  браузер) поднимают заново из скрипта, не из памяти.
- Перед повторным запуском убирай lock-файлы погибшего инстанса (`SingletonLock`, `*.lock`),
  иначе процесс молча выходит.
- Библиотеки и каталоги проектов часто одноэкземплярные: второй запуск на ту же папку падает с
  «already open (process N)»; работа с уже запущенным окном идёт через control-порт приложения.

## 4. Программное управление — сначала ищи встроенное

Прежде чем писать обёртки, проверь у приложения CLI и MCP: десктопные приложения всё чаще возят
`<app>-cli mcp` с собой. Как подключать такие серверы к Hermes, режимы headless/bridge и границы
доступа к файлам — навык `native-mcp`: его `references/bundled-app-mcp.md` и `scripts/mcp_probe.py`.

## 5. Документация — локально, без исходников

Когда нужна только дока (а репозиторий весит гигабайты идей и картинок):

```bash
git clone --depth 1 --filter=blob:none --sparse <repo> <dir> && cd <dir> \
  && git sparse-checkout set docs book   # пути взять из листинга репозитория
```

Проверь, что каталоги действительно появились (`ls docs | wc -l`): `--sparse` без успешного
`sparse-checkout set` оставляет только корневые файлы.

## 6. Отчёт и след в базе знаний

Установка без записи в хранилище теряется. После проверки — заметка в Obsidian
(`Knowledge/<Название> — <что это>.md`): что за продукт, таблица версий и путей, как подключено
программно, грабли, ссылки; плюс строка-ссылка в `MOC — Index`; затем commit и push в репозиторий
хранилища. В ответе — только проверенное: версия из `--version`, живые вызовы, что не проверено.

## Питфоллы

- **В automation-режиме часть команд выключена намеренно.** У PhotoCraft `file.placeEmbedded` возвращает
  «uses ambient filesystem paths and is disabled; use capability-scoped document methods» — пути вне
  read/write-корней запрещены, и вставка картинки «из ниоткуда» тоже. Рабочая схема замены фона без GUI:
  `doc_open(фото)` → `select.subject` (это настоящая ИИ-выделение объекта, работает headless) →
  `select.inverse`/`layer.new.layerViaCopy` → спрятать исходный слой `layer.setProps{visible:false}` →
  `doc_export(png)` с альфой → композит в PIL (маска из альфы, дилатация `MaxFilter(5)` + блюр 2px).
  Проверять результат глазами (`vision_analyze`), а не по коду возврата `null`.
- **Маска ИИ врёт на краях кадра.** На фото «люди в ванне» `select.subject` посчитала размытую воду
  у нижней кромки фоном и открыла там подложку — лечится отсечкой маски по строке, вычисленной из
  профиля прозрачности по строкам (`trans.sum(axis=1)`), а не на глаз.

- **Не путай «подключено» с «работает».** `--version` и `list` показывают наличие; доказательство —
  реальный вызов (инструмента MCP, экспорт файла, рендер превью).
- **Не ставь GUI-приложение в системный путь без нужды** — обновление потребует рута, а откат —
  переустановки. Распаковка в свой каталог даёт дешёвый откат: рядом лежит старая версия.
- **Не запускай второй инстанс на тот же профиль/библиотеку**, пока не проверил lock-файлы: замок
  держит либо живой GUI, либо фоновый потомок агента, и сообщение об ошибке называет только pid.
